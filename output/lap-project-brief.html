Living Agents Protocol

The existence layer for always-on AI agents — an open standard project by Athar Nouman.

§1 · What this is

AI agents recently got standard ways to use tools (Anthropic's MCP), exchange tasks (Google's A2A), and pay (AP2, x402). But nothing standardizes an agent's existence: who it is, which human or company answers for it, what it may do while unsupervised, whether it's running right now, what it remembers, and how its actions are proven afterwards. LAP is an open reference model plus concrete wire mechanisms for that missing layer — the TLS-handshake role for agents: it never carries the work, it decides whether, and under whose authority, work may flow.

Agents need a birth certificate, a leash, a black box, and an estate plan.

§3 · The plan — publish, then infiltrate

Deliberately not a consortium (strategy reviews killed that): LAP is a byline, not a body.

  1. Publish. Film the 90-second demo; open the repo (Apache-2.0 code, CC-BY spec); release the essay and arXiv paper — code first, claims second.
  2. Infiltrate. File mechanisms as extensions where distribution already lives: MCP/A2A middleware (~60% of effort), the W3C AI Agent community, OWASP agentic security; watching the new ITU and NIST agent-standards efforts.
  3. Day-60 gate. Objective pull signals (external PRs, a framework plugin accepted) decide what gets doubled down; dead tracks are archived, not nursed.
  4. The tripwire. Two external implementations we didn't recruit unlocks the bigger institutional ambitions — held in reserve until earned.
§4 · Honest odds

Three ways this wins: LIKELY the concepts get absorbed into larger standards with attribution · LIKELY it establishes deep, demonstrated expertise in agent identity and lifecycle · LONG SHOT LAP itself becomes the referenced existence layer if the agent economy arrives on schedule. The project is structured so any one of the three justifies it.

§5 · The meta-story

The spec was built with AI as a genuine collaborator: drafted with Claude, then attacked across multiple frontier models under a structured review kit — every external finding verified before merging, duplicates deduplicated, rejections logged publicly. Arguably one of the first protocol specs hardened this way, and that is part of the point: this is what accountable human-plus-AI systems engineering looks like.
