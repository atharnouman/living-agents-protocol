# The Living Agents Protocol: A Reference Model and Research Agenda for Persistent Autonomous Agents

**Athar Nouman**
*Draft for arXiv (cs.MA; cross-list cs.CR), v1.2-draft — September 2026. Specification, code, and materials: https://github.com/atharnouman/living-agents-protocol. License: CC-BY-4.0 (text); reference code Apache-2.0.*

## Abstract

Recent protocols give AI agents hands (MCP, for tools), voices (A2A, for tasks), and wallets (AP2, x402, for payments). None of them addresses *existence*: what it means for an agent to persist — to hold an identity across restarts, a memory across vendors, bounded authority while unsupervised, evidence of its own liveness, and a human who ultimately answers for it. As always-on agents move from demos toward production, every one of these becomes a prerequisite for trust between strangers, for insurability, and for regulatory compliance — and every one is unstandardized. We propose the Living Agents Protocol (LAP): a modular reference architecture for persistent agents that assigns existing protocols their coordinates and specifies the missing control plane as drop-in profiles of ratified standards (including a one-page "Micro-Core" adoptable by a single tool server) rather than a monolithic suite — a seven-layer map in the OSI tradition, delivered with running code and test vectors. We contribute concrete candidate mechanisms for the missing layers — witnessed genesis records, autonomy envelopes with liveness-conditioned decay, a six-step stranger handshake, era-stamped portable reputation, tamper-evident flight recorders, and clean agent retirement — and, with equal weight, a set of open problems (semantic scope algebras, principal proofing, key custody, the limits of behavioral certification) that we argue must be solved before any certification regime for autonomous agents can be honest. We position this work deliberately as a reference model and research agenda: the mechanisms are offered as candidate extensions to existing venues (A2A extensions, the W3C AI Agent Protocol effort, OWASP's agentic-security work, on-chain identity registries), not as a rival protocol suite.

## 1. Introduction

Between 2024 and 2026 the agent ecosystem acquired its communication substrate at remarkable speed. The Model Context Protocol standardized how agents reach tools and context. Agent2Agent standardized how agents exchange tasks, and moved to neutral governance within months. Payment mandates (AP2) and HTTP-native settlement (x402) gave agents the beginnings of an economy. It is now reasonable for two software agents, operated by strangers, to discover each other, exchange work, and move money.

It is *not* yet reasonable for either of them to trust the other — and the reason is structural, not incremental. All current protocols treat an agent as a request/response endpoint: something that exists for the duration of an exchange. But the agents now being deployed are increasingly *persistent*: they run continuously, schedule their own work, accumulate memory, act while their operators sleep, and spawn sub-agents. A persistent agent is an entity with a lifecycle, and lifecycle raises questions that request/response protocols never had to answer:

- **Identity**: who is this agent, who does it act *for*, and who spawned it — provably, and stably across process restarts and host migrations?
- **Authority**: what may it do *without a human*, with what budgets, and how does that authority end when supervision ends?
- **Liveness**: is it operating right now? What happens to its permissions when it goes dark?
- **Memory**: what does it remember, who owns those memories, and what happens to them when the agent changes vendor, owner, or model?
- **Evidence**: when it acts overnight, what record exists that an auditor, insurer, or court could rely on?
- **Death**: how does an agent retire without leaving orphaned credentials and zombie authority behind?

Each of these has partial answers scattered across workload identity (SPIFFE), delegated authorization (OAuth, GNAP), verifiable credentials, transparency logs, and observability conventions. None has an agent-shaped answer, and no framework relates them. This paper proposes the frame.

**Contributions.** (1) A seven-layer reference model, LAP-7, that assigns existing protocols coordinates and isolates the genuinely unowned concerns (§3). (2) Candidate mechanisms for those concerns, specified to the level where their failure modes can be critiqued (§4). (3) An explicit account of what certification-style assurance can and cannot establish for stochastic systems (§5). (4) An open-problems agenda we believe is load-bearing for the whole area (§6). (5) A deployment path that files these mechanisms into venues that already have distribution (§7).

**Non-goals.** We do not propose new task, tool, or payment protocols; we bind to MCP, A2A, and AP2/x402. We do not operate — and argue nobody should yet operate — a certification program (§5). We make no claim that the stranger-agent economy is imminent; we claim that *if* it arrives, these are the questions, and that several of the mechanisms pay their way even in single-operator deployments today.

## 2. Related work and the lesson of the prior generation

**Current protocol layer.** MCP (agent↔tool), A2A and ACP (agent↔agent tasking; A2A's Agent Cards are capability descriptors that our passports extend with principal, lineage, and policy commitments), AP2 (payment mandates — the closest existing artifact to a scoped authority grant) and x402 (HTTP-native settlement).

**Identity and registries.** Decentralized identifiers and verifiable credentials; SPIFFE/SPIRE for workload identity; enterprise agent-identity products (e.g., directory-native agent IDs); AGNTCY's identity/discovery/observability stack; ERC-8004's on-chain identity, reputation, and validation registries; academic and community registry efforts (e.g., NANDA); the W3C AI Agent Protocol Community Group. This space is active and fragmented; our contribution is not another registry but a neutrality architecture (§4.6) and field-level requirements (principal binding, lineage, proof-class labeling) that any of these could carry.

**Governance frameworks.** The EU AI Act's logging and post-market-monitoring duties, NIST AI RMF, ISO/IEC 42001, and OWASP's agentic-security threat work define obligations and threats, not wire formats. We treat them as crosswalk targets.

**The prior generation, diagnosed correctly.** Agent communication standards have been tried: KQML in the early 1990s, FIPA-ACL from 1996 (an IEEE standards committee by 2005), Contract Net before both. It is commonly said that FIPA failed for lack of implementation. This is false — JADE was a real, maintained, widely used FIPA platform for over a decade. FIPA failed because the economy of interoperating stranger agents it presupposed did not arrive, and because its semantic layer (ontologies, content languages) demanded agreement the world had no incentive to produce. The same demand-failure killed the stranger-discovery registries of the web-services era (UDDI, shut down after five years of vendor operation) and the machine-readable-policy disclosure of P3P. More recently, the self-sovereign identity stack (DIDComm, Aries, Trust-over-IP) built peer identity, connection handshakes, and mediated store-and-forward — for *humans*, a larger market — and found minimal voluntary adoption.

We take two design rules from this history rather than a slogan. First, *timing-hedged design*: every mechanism should be adoptable piecemeal by a single operator, with value before any ecosystem exists, because the ecosystem may be years away. Second, *the semantic layer is the graveyard*: any mechanism whose enforcement depends on shared meaning must ship with a deliberately tiny, closed vocabulary or it ships nothing (§6.1).

## 3. The LAP-7 reference model

Seven layers, bottom-up. Each answers one question; security is a per-layer conformance requirement, not a layer. Existing protocols slot in at Layer 6; the model's claim to novelty is the six layers of *being* below it and the layer of *answering* above it.

| # | Layer | Question | Existing tech slotted | Missing (this work) |
|---|-------|----------|----------------------|---------------------|
| L7 | Accountability | How do humans see, steer, and answer for it? | OTel GenAI, AI-Act logging duties | Flight recorder format; override verbs; the Human Escalation Guarantee |
| L6 | Society | How does it deal with others? | **MCP, A2A, AP2/x402**, marketplaces | Stranger handshake; interaction contracts; era-stamped reputation |
| L5 | Volition | What may it do without a human? | OAuth/GNAP, AP2 mandates, macaroons/biscuits, policy engines | Autonomy envelopes; autonomy levels; liveness-conditioned decay |
| L4 | Vitality | Is it alive right now; where in its life is it? | health checks, queues, presence concepts | Lifecycle states; pulse/witness model; sleep-aware sessions; retirement |
| L3 | Memory | What does it remember; whose is it? | vector stores, memory vendors, GDPR portability | Portable memory format; provenance/consent classes; forget-propagation |
| L2 | Identity | Who is it, provably? | DID/VC, SPIFFE, attestation, on-chain registries | Passport: principal binding, lineage, policy commitment, proof classes |
| L1 | Substrate | Where does it run? | OCI, microVMs, WASM, TEEs | Runtime profile (tokens as metered resource); migration semantics |

A condensed five-layer implementer's profile, **ALIVE**, collapses L1–L3 into *Essence* and reads, top-down: **A**ccountability, **L**iaison, **I**ntent, **V**itality, **E**ssence.

We also propose a six-level autonomy vocabulary (AL-0 tool → AL-4 delegating autonomous, with AL-5 defined but explicitly *not certifiable*), in the spirit of SAE J3016's role for driving automation: a shared answer to "how unsupervised is this system?", declared in the passport and bounded by the envelope.

## 4. Candidate mechanisms

Space permits sketches; the specification carries details. Each mechanism is stated with its honest limits. Wire mechanics are, wherever possible, direct profiles of ratified standards — RFC 9421 (HTTP message signatures), RFC 8785 (JSON canonicalization), RFC 6962 (Merkle trees), W3C VC 2.0, OAuth RAR/GNAP, Biscuit — while the novel contributions are the semantic rules layered on them (pulse-gated suspension, era-stamping, the scope algebra's entailment rules, the handshake's disclosure ceremony).

**4.1 Agent Passport and Genesis Record (L2).** A signed document binding: agent identifier; *principal* (the human or organization it acts for, with a labeled proof class — self-asserted, domain-, organization-, or government-validated, because a uniform "proof" field would launder weak attestations); *lineage* (spawner, generation); a *constitution hash* — honestly framed as a **public policy commitment**, not a behavioral attestation: it proves which rules were promised, enabling review of logged actions against the charter's mechanical rules, and no more; declared autonomy level; presence contact; revocation endpoint. The Genesis Record is the passport's birth event, submitted to independent transparency logs at creation so the timestamp is *witnessed rather than self-asserted* — making agent age a usable, unforgeable trust signal. Later passport mutations (principal handoff, key rotation) form a logged amendment chain traced from Genesis. Normative rule: **no orphan agents** — every passport resolves to a responsible legal person.

**4.2 Autonomy Envelope with decay (L5).** A signed, attenuable mandate: scopes drawn from a closed algebra (§6.1, Appendix A), budgets, counterparty classes, time windows, escalation tree, expiry. Two properties distinguish it from a scoped token. First, **decay**: envelope validity is conditioned on the agent's heartbeat continuity — an agent that goes dark loses its authority by protocol. We specify this against the lessons of PKI revocation: an explicit witness/observer model; hard-fail only for money and PII scopes and soft-fail with staleness labels elsewhere; suspension that is prospective only (in-flight actions complete or roll back per contract), while a principal's explicit emergency revocation is a distinct act that does reach in-flight work — halt stops authority, never debts already incurred; and a multi-witness quorum so that jamming an agent's pulse path cannot be weaponized into stripping its authority. Second, **an enforcement locus for budgets**: a signed envelope is a capability, but a budget is mutable state; without a named *spend authorizer* (the principal's authorization endpoint, or rail-side caps via payment mandates), a budget presented to ten counterparties authorizes ten times the limit. The specification therefore demotes authorizer-less budgets to *disclosure of intent* — they allocate liability; they do not bound spending.

**4.3 Pulse (L4).** Periodic signed heartbeats chained to the audit-log head. Honest semantics: a pulse proves **continuity of key custody and operational responsibility**, not inner life; its status fields are self-reported; its power lies in what its absence triggers. Lifecycle states (active, dormant, incapacitated, retired, archived), sessions bound to the passport rather than the process (a restart is a nap, not a death — demonstrated in the networked reference demo, where a seller process is killed, restarted with its persisted identity, and the counterparty's authority restores automatically), and a retirement protocol — revocation, archival, and consent-filtered disposition of memory — complete the layer. Retirement matters more than it appears: orphaned non-human credentials are a leading current identity risk, and agents that never legally die accumulate zombie authority indefinitely.

**4.4 MEET, the stranger handshake (L6).** Six steps: HAIL (exchange passports), PROVE (mutual challenge, revocation and registration checks, signed-tree-head gossip against split-view registries), CHARTER (two-stage: commitments and predicate proofs first — backed by authorizer-signed reservation tickets so concurrent handshakes cannot over-subscribe one envelope — with full disclosure deferred into the signed contract), TUNE (negotiate transports: A2A, MCP, payment rails), BIND (a signed interaction contract: purpose, data terms, logging duties, dispute pointer, the Human Escalation Guarantee clause — logged by both, with countersigned, fair-exchange turn closure), PULSE (a presence contract: heartbeat cadence, store-and-forward across sleep, resumption keys). Every message signs a transcript hash of the whole preceding conversation. Disclosure is simultaneously a *legal shield* — under agency doctrine, disclosed limits defeat later apparent-authority claims against the principal — and a reconnaissance risk, which is why the two-stage structure exists.

**4.5 Ownership, transfer, and era-stamped reputation (L6/L7).** We distinguish *owner* (title: the right to transfer, lease, retire) from *principal* (accountability: whom it acts for). Title transfer is a two-phase signed ceremony with three safety rules: all envelopes **auto-revoke** at transfer (otherwise buying an agent means buying the previous owner's bank permissions); clones receive a fresh genesis and zero tenure (reputation is *soulbound* to the individual identity — the train-one-sell-a-thousand attack dies here); and reputation itself is carried as **era-stamped receipts** — counterparty-signed completions recording the substrate era (a runtime-environment digest, two-track for self-hosted versus API-hosted models) under which they were earned. Era-stamping resolves an otherwise fatal contradiction between memory portability and reputation integrity: an agent migrated to a new model keeps its continuous history, but counterparties see exactly which substrate earned which receipts, so reputation is portable without being launderable. Accountability itself forms an unbroken chain across the agent's whole life — voluntary principal handoff, sale, death-triggered succession with attested legal evidence and a logged challenge window, and estate closure — with the invariant that a break in the chain freezes authority automatically rather than freeing the agent. Self-ownership is excluded by construction: title must terminate in a legal person, which is what keeps the rest of the model insurable and regulable.

**4.6 Registration without a gatekeeper (L2/L7).** Registry neutrality is stated as properties, not a chain choice: permissionless admission; censorship resistance; rewrite-evidence; verifier equality; operator mortality (the record must outlive every operator). Architecture: transparency logs profiled on IETF SCITT, periodically **anchored to open permissionless blockchains** (Merkle aggregation buys chain-grade finality at any birth rate without per-agent transactions, chain lock-in, or personal data on-chain — principal references are salted blinded commitments, erasable by salt destruction), plus a **self-anchoring escape hatch** — if every log refuses an agent, a direct on-chain anchor is first-class registration once finalized. We are explicit that this architecture is operationally orphaned today (Certificate Transparency worked because a browser mandated it; no analogous forcing function exists yet for agents) and present it as the design to reach for *when* a forcing function emerges, with the escape hatch ensuring that whoever operates logs never controls existence.

**4.7 Flight Recorder (L7).** A hash-chained, privacy-tiered event log with pulse-countersigned heads. Honest framing: tamper-*evidence* is not completeness — the sensor, pilot, and scribe are one process, so the recorder is the agent's *admissions*: strong for demonstrating compliance with an envelope, weak for proving absence of action. Bilateral events become dual-entry through BIND; unilateral completeness would require attested execution beyond current practice for API-hosted models. Even so limited, a standardized admissions format is the artifact that audit duties (and, eventually, underwriting) will need.

## 5. What certification can and cannot establish

The natural endpoint of a trust model is a certification mark, and the area is already acquiring certification ambitions (including insurer-native standards). We argue for restraint grounded in two structural limits. First, conformance testing of an agent endpoint certifies *wire behavior and policy shims under observation by a harness that must cryptographically identify itself* — the tested system knows it is being tested, and stochastic systems bound nothing about their tails from N clean trials. Second, charter fidelity beyond mechanical rules is qualitative review, not verification. Certificate language must therefore say "this endpoint implements the protocol," never "this agent is safe"; behavioral assurance, if it is achievable at all, will require continuous covert probing rather than point-in-time physicals. We defer all certification operations and offer the conformance suite design as a commons.

## 6. Open problems

We consider these load-bearing for the field, not merely for LAP.

1. **The scope algebra.** Attenuation cryptography proves *derivation*; only within a closed semantic algebra does it prove *entailment* (that a child's permitted actions are a subset of its parent's). Our candidate design (Appendix A) uses registry-DAG action subsumption, two-dimensional caps, and envelope-level budget conservation; whether such an algebra can stay small under real demand is open — its uncontrolled growth is how this generation of agent standards would re-run FIPA's death.
2. **Principal proofing.** Binding identifiers to legal persons at consumer scale is KYC/eIDAS/LEI territory; until that issuer ecosystem exists, "who do you act for?" is answerable only up to a labeled proof class.
3. **Key custody and recovery.** The root of all authority here is a signing key; consumer custody sank client certificates and PGP. A compromised principal key signs authorized-looking envelopes, and the flight recorder then faithfully launders the attack. Custody classes, social recovery, and hardware anchors are the space; no answer is standard.
4. **Liveness witnessing.** Autonomy decay requires an ecosystem of independent pulse witnesses that does not exist; its economics (who runs monitors, and why — our candidate: flat per-epoch retainers, decoupled from traffic to prevent griefing) are the CT-operations problem in miniature.
5. **Recorder completeness and attested delegation.** Proving what an agent did *not* do, and proving a delegation graph complete, both require attestation of execution beyond current practice for hosted models.
6. **Memory portability vs. representation.** A portable memory format ports the diary, not the mind: embeddings and fine-tuned behavior are substrate-bound. What re-embedding does to retrieval behavior across substrates — and thus what "the same agent" means after migration — is an open empirical question that era-stamping makes visible but does not answer.
7. **The clone / single-writer problem.** A signing key is copyable, so a snapshot restore, an autoscaler, or an active-active deployment can run two indistinguishable live copies of one agent — same identifier, same passport, same resumption material. Both can extend one accepted handshake state with different valid next turns, and both can emit valid pulses; per-session replay caches detect the fork only after a payment or disclosure may already have occurred. The model's "one living identity" and "a pulse proves continuity of custody" statements are therefore aspirations the current mechanisms do not enforce. The honest resolution is a choice the specification has not yet made: *singleton* semantics, requiring a linearizable identity-instance lease whose fencing epoch is carried by every pulse, transition, and receipt (with a signing layer that refuses stale epochs); or *fleet* semantics, replacing "one being" with a replicated-state-machine profile. We consider this the deepest open problem in the model. It was surfaced by an external hostile audit — itself an argument for the review process described in §7.

## 7. Deployment path

Consistent with the timing-hedge, we do not propose a new body. The mechanisms are being filed where distribution already lives: the autonomy envelope and decay as a proposed A2A extension; lifecycle, pulse, and presence into the W3C AI Agent Protocol Community Group; the accountability floor and trust states toward OWASP's agentic-security effort; principal-binding, lineage, and era-stamped-receipt fields as companion commentary to on-chain identity/reputation registries (e.g., ERC-8004) and AGNTCY identity work; the flight-recorder format toward insurer-native standards efforts as a partner track. Two interoperating reference implementations (a zero-dependency Node library and a Python port with FastMCP middleware), deterministic cross-language test vectors, a two-stranger overnight demonstration that runs as two real processes over real sockets (IPv4 and IPv6, with a genuine process kill and restart), a ten-check conformance challenge for independent implementations, registration of Genesis Records in a public transparency log (Sigstore Rekor) with the inclusion proof and signed timestamp verified by the reference code, a property-based fuzzer whose cross-implementation decision digest fails the build on any disagreement, a written threat model, a tutorial that binds Micro-Core to an MCP server through the official SDK, and an experimental git binding — an agent passport and path envelope enforced before a commit exists — accompany the specification. The git binding exists because the project itself experienced the failure it prevents: an AI agent contributing to the repository made an unattributed, out-of-scope commit, documented publicly as a case study. The consortium, certification, and registry designs are published as blueprints in reserve, activation-gated on independent external implementation.

## 8. Conclusion

The last three years standardized how agents talk, task, and pay. The next set of questions — who they are, what they may do alone, whether they are alive, what they remember, who answers for them, and how they die — is currently answered by nobody, and the history of agent standards says these questions become urgent suddenly, after a long period of appearing academic. This paper's bet is disciplined: a map that gives existing protocols their places; mechanisms honest about their limits, adoptable one at a time, by one operator, today; and a research agenda stated plainly enough to be attacked. If the persistent-agent economy arrives, the existence layer will be standardized by someone; we would rather the field inherit a design that has already survived its own red team.

## Appendix A — Scope Algebra v0: formal core

**A.1 Scope subsumption.** A child scope c attenuates a parent scope p (c ⊑ p) iff all hold: (i) equal algebra versions; (ii) action: p.act = c.act or (p.act, c.act) is a declared edge-path in the versioned action registry DAG — string prefixing confers nothing; (iii) resource: segment-tokenized path subsumption (wildcards terminal-only; `*` = exactly one segment; dot-segments and encoded separators rejected; comparison is textual after normalization, so IPv6 host literals must use RFC 5952 canonical form [11, 12]); (iv) counterparties: with E(X) = (X.allow ≠ ∅ ? X.allow : U) \ X.deny, require E(c) ⊆ E(p) and p.deny ⊆ c.deny; (v) depth: c.depth ≤ p.depth − 1; (vi) decay: c.decay ≤ p.decay.

**A.2 Two-dimensional caps.** With identical units required: c.max_per_tx ≤ p.max_per_tx; if p carries a time window, c must also, with Duration(c.w) an integer divisor of Duration(p.w) and c.max_cumulative ≤ ⌊p.max_cumulative · Duration(c.w)/Duration(p.w)⌋ (integer floor, for cross-implementation determinism). A bare per-transaction window cannot attenuate a windowed parent (rate-unboundedness), and `epoch_total` attenuates only to `epoch_total`.

**A.3 Envelope budget conservation.** Child scopes are matched to parent scopes greedily in canonical (JCS-sorted) order, each match debiting a per-parent remaining-budget tracker; the sum of child cumulatives matched to one parent scope never exceeds that parent's cumulative. The procedure is sound (never accepts an invalid set) and deliberately incomplete (greedy matching may reject sets a different assignment would satisfy); the canonical order makes all implementations agree on the verdict. Conservation across *separately issued* sibling envelopes is an issuer-side duty.

**A.4 Reference-implementation measurements** (Node 20, consumer laptop, zero-dependency implementation): passport verification (Ed25519 JWS + claim checks) ≈ 0.30 ms/op; Merkle inclusion-proof *verification* — the counterparty hot path — ≈ 0.11 ms/op; proof *generation* in the naive un-memoized reference log is O(n) per call (≈ 93 ms at 10⁴ leaves) — production logs memoize subtree hashes.
